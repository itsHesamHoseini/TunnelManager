# Contracts
C24 Engine retirement: the owner removed the second engine from product scope. No host unit, binary, configuration, firewall or listener is stopped/deleted/rewritten by retirement. Database cleanup is one-way and transactional: refuse pending mutations, take and verify a root-only encrypted snapshot of owned tables before any delete/update, remove retired-only records/dependencies/reservations, prune only retired members from mixed history and preserve supported-engine records byte-for-byte when unaffected. Rollback the transaction on backup/decryption/conflict failure. Generic actual listener conflict detection remains engine-independent. Tests must use populated mixed-engine PostgreSQL and retained dependencies, not an empty schema. A release cannot claim removal until its explicit source allowlist, browser and real Backhaul native checks pass.
C23 Owner-approved ordinary editor: six field concepts only; repeatable entry-port/backend-host/backend-port mappings, loopback destination on the selected backend peer by default, shared transport port/kind/token applied through existing coordinated plans. Preserve role-scoped advanced options and supported raw configuration, secret placeholders, shared-route impact and drift/revision checks. Explain interruption, port changes and affected peers in plain-language preview; retain the explicit post-apply 90-second confirm/revert window.
C22 Owner revision v2: current node health requires explicit approval, a connected authenticated agent and a non-future observation no older than 90 seconds. The API reports a shared online state and evidence-based reason. UI recomputes age as time passes and invalidates current values after a failed refresh; historical samples remain labelled historical. Missing metrics are never zero/healthy. CPU/RAM/used-disk thresholds: below 70 normal, 70 through 90 high, above 90 critical; stale values have neutral styling and explicit last-observed time. One isolated timestamp component renders relative time and a complete calendar-aware tooltip. Message codes are hidden in expandable technical details; unknown codes have a localized generic explanation and next action. Error JSON request_id equals the server-generated X-Request-ID and never trusts a client-supplied identifier. Refer to REVISION-2.md for decisions/evidence still pending.

C1 HTTP: JSON errors include stable code, English/Persian message, request ID. Bodies <=64 KiB. Origin checking on writes, Secure HttpOnly SameSite=Strict cookies, hashed session tokens, 12-hour session expiry.
C2 Authentication: Argon2id hashes, bounded expensive-password work; equal unknown-user hashing. Password creates a 2-minute single-use challenge. MFA success rotates to an authenticated session; pending TOTP sessions may only enroll. TOTP replay prevented with monotonic step. Recovery codes stored as hashes, consumed atomically.
C3 Agent identity: enrollment token hashed, expires in 10 minutes, consumed exactly once. Node generates Ed25519 key locally; controller stores public key. Approval required before telemetry/actions. Signed nonce binds node ID, expiry and a fresh challenge. TLS verification cannot be disabled. Frames <=256 KiB, one connection per identity, heartbeat <=30 seconds.
C4 Telemetry: server ID, sample time, scope, CPU deltas, RAM, disk, interfaces, processes, listeners and service metadata. No config contents, environment or process argv. Freshness <=90 seconds. Host network counters are never labelled per-tunnel usage.
C5 Actions: typed IDs and bounded values only. The approved v2 adapters implement management under C11–C19; v1 remains telemetry-only. Unknown actions and arbitrary shell/program text are rejected.
C6 Installer: preview before mutation, atomic state marker, restricted runtime directory, secrets separate from DB, explicit Compose names. Only edge port published; no Docker socket in controller. Rerun keeps secrets/data. Update stages verified binary/UI, snapshots before cutover and restores on failed health.
C7 Maintenance: backup encrypted with independent passphrase, includes DB plus runtime key/config; never prints private material. Restore authenticates before changing anything and requires empty destination or explicit replacement confirmation.
C8 Data removal: explicit keep-data=false removes only the installer-owned postgres subtree. Ownership must match the installation/config directories and every existing parent must resolve without symlinks. Exported backups and unrelated files remain preserved. A populated unowned data directory is never silently adopted.
C9 Native node repair: snapshot executable/config/owned unit before replacing them; failed repair restores the previous unit and its active/enabled state. A failed fresh installation removes only its newly created unit and leaves identity material for explicit repair; pending controller records remain visible.
C10 Reinstall: keeping data retains its marker and setup starts only the owned database before snapshotting it; explicit purge clears its installation marker and obsolete credentials. Moving config/data directories requires authenticated backup and restore into a fresh installation, never an implicit mount change.

C11 Operations v2: approved signed TLS channel supports telemetry plus bounded command polling. Each typed command has a durable UUID, immutable payload digest, expiry and node target; receipts on the node make retries idempotent. No arbitrary programs/shell/paths. One in-flight action per node, two global workers; command payloads with secrets are encrypted in PostgreSQL and never returned as operation logs. Version-1 telemetry remains compatible and cannot execute commands.
C12 Tunnel model: independent ingress bind, engine transport listener/dialer and backend endpoint; a listener node and dialer node determine reverse connection direction independently from traffic direction. One instance may contain many routes. Form settings and validated TOML refer to the same revision. Raw previews/diffs redact tokens and private keys, preserving unchanged secret values.
C13 Ownership/discovery: discovery reads actual systemd/PID/config evidence only; no installation/adoption/rewrite. Route pairing records its evidence and ambiguity; manual import selects both instances/routes and is read-only. Adoption explicitly registers the selected unit/config/binary and expected hashes. Every later mutation checks that evidence and shows all affected routes.
C14 Change protocol: preview validates both nodes, engine version, config, certs, destination and port conflicts; reserved node/port/protocol/bind ranges serialize pending plans. Apply snapshots and prepares both sides before activation. Each node arms a persistent local rollback timer before touching its unit/config. Failed/disconnected/unconfirmed changes revert locally; controller records partial/recovery outcomes. Explicit confirm within 90 seconds commits only after both sides pass checks. Manual file drift or stale revisions block overwrite. Intentional stop/disable is durable.
C15 Diagnostics/logs: typed finite TCP/TLS/HTTP/echo/ping/speed requests have bounded time/bytes and recorded source/target/time. Service active, control TCP/TLS and application reachability are independent observations. Unconfigured application checks remain unknown. Logs are bounded, redacted and searchable; causes are labelled probable. No environment, arbitrary file reads or shell text.
C16 Certificates/recovery: private material encrypted outside node-local root-only files; deploy only to explicitly linked managed instances, with backups/drift checks and reload impact. ACME prerequisites and provider failures are explicit. Recovery targets an adopted/managed unit only, requires sustained thresholds, cooldown, daily limits and persists intentional stops/restart reasons. Panel outage does not stop engines or cancel local rollback.

C17 Completion details: batch mutations preview the transitive shared-instance impact and validate every selected revision; each distinct node/instance executes once. Revoking management preserves its files/unit and removes ownership only. Temporary verbosity is explicitly confirmed, bounded to 1-10 minutes and restored by an independent local timer; other config changes wait. Raw/form/import preserve supported role-scoped options and reject unsupported identity/proxy semantics instead of silently dropping them. Certificate policy has independent compare-and-swap metadata; issued revisions and deployed revisions remain distinguishable.

C18 Maintenance: alert timing is bounded/configurable; unknown or disconnected peers invalidate current health without rewriting historical evidence. Node receipt retention is 24 hours (expired commands are rejected first); finalized local backups/journals/events retain 30 days, active watchdogs are never pruned. Each maintenance pass has a one-second I/O budget and runs at most hourly. Release builds embed a semantic version and source commit without wall-clock timestamps; publication waits for successful exact-source native workflows.

C19 Recovery review: manual config/unit drift also blocks unconfirmed rollback. An explicitly confirmed release of a failed recovery disarms only that operation's local timers and preserves current files/services; its backups remain. It does not claim a successful rollback. Affected old tunnel revisions become observation-only until fresh discovery/import/adoption. Existing unmatched services may be adopted individually using fresh signed hashes, without rewriting/restarting them. Manual reimport may refresh observation-only records but cannot overwrite managed revisions.

C20 Native format boundary: documented integer engine options must render as TOML integers after JSON/persistence round trips. Fractional or out-of-range values remain rejected by the existing adapter validation; no option/permission expansion. Native startup/traffic tests must exercise scoped numeric settings, not substring-only assertions.
# C21 — reference console and DNS evidence
Existing authenticated mutation APIs, idempotency, draft guards and durable jobs remain authoritative. Route rows flatten logical routes while preserving the parent tunnel and independent user/transport/backend endpoints. Discovery queues bounded inventory jobs for selected approved nodes and shows every result; selection does not adopt. Correlation may resolve validated hostnames against signed node addresses with a bounded deadline/cache. Only fresh unique engine/role/transport/port/authentication/route evidence creates an observation record. Ambiguity, stale evidence or DNS failure never grants management or health. Tests inject the resolver; authentication matching material never enters API responses.
Node metadata adds optional `country` (two uppercase ASCII letters, or empty); existing CAS applies. Flags are bundled assets with a globe fallback. Read-only tunnel previews show the redacted discovered configuration, including options unsupported by the managed renderer. A server summary's actions open the actual services/network/history workspace, and route tabs open the parent tunnel's real status/actions/history/settings. No alternative mutation endpoint is introduced.
Redaction traverses TOML tables, array tables and nested inline arrays before any configuration preview is returned. Unsupported options remain visible as evidence only after secret-named fields are masked; retaining evidence never permits secret disclosure or unsupported management.
