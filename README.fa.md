# TunnelManager
پنل مدیریت و عیب‌یابی Backhaul و Rathole؛ فارسی راست‌چین و انگلیسی، روشن و تیره. عامل هر سرور از داخل به پنل وصل می‌شود. خاموشی پنل، تونل‌ها را متوقف نمی‌کند.

نسخهٔ ۰٫۷، نمای کلی، مسیرها، سرورها و دیسکاوری را به ابزارهای واقعی سرویس وصل می‌کند و جفت‌های دارای شاهد کافی را بدون پذیرش مدیریت نمایش می‌دهد. [شواهد آزمون و استقرار](docs/CONSOLE-0.7-REPORT.md) · [راهنمای کار روزمره](docs/QUICKSTART.fa.md)

## نصب
Ubuntu 22.04 و 24.04 و Debian 12 آزمایش لینوکسی دارند. فایل ARM64 ساخته می‌شود؛ اجرای بومی ARM64 و Debian 11 هنوز آزمایش نشده است.
```sh
curl --proto '=https' --tlsv1.2 -fsSLo install.sh https://raw.githubusercontent.com/itsHesamHoseini/TunnelManager/main/install.sh
less install.sh
sudo sh install.sh setup --with-local-node
```
نصب‌کننده پیش از اجرا SHA256 را بررسی می‌کند. راهنما دامنه، پورت، گواهی و حساب مدیر را می‌پرسد و پیش از تغییر خلاصه نشان می‌دهد. نصب Docker انتخاب صریح است. پورت پیش‌فرض 9443 است. ورود دومرحله‌ای و نگهداری کدهای بازیابی را خود مدیر انجام می‌دهد. [نسخهٔ منتشرشدهٔ v0.7.0](https://github.com/itsHesamHoseini/TunnelManager/releases/tag/v0.7.0) دریافت و اجرای واقعی نصب‌کننده را پاس کرده است. [حدود پشتیبانی](docs/RELEASE-NOTES.md) و روش ساخت از سورس در README انگلیسی آمده است.

## کار روزمره
[راهنمای مرحله‌ای کار با پنل](docs/QUICKSTART.fa.md)
۱. از «سرورها ← افزودن سرور» دستور عامل و توکن یک‌بارمصرف بگیرید. توکن در ورودی مخفی وارد می‌شود. هویت سرور را بررسی و تأیید کنید.

۲. کشف را اجرا کنید. کشف، سرویس را تغییر نمی‌دهد. سرویس بدون جفت در فهرست می‌ماند؛ در صورت ابهام دو طرف را دستی جفت کنید. تغییر زیرساخت موجود نیازمند پذیرش مدیریت است.

۳. موتور تأییدشده را نصب کنید. ورودی کاربر، ارتباط بین سرورها و مقصد نهایی مستقل‌اند؛ جهت اتصال موتور نیز جدا نمایش داده می‌شود.

۴. تفاوت تنظیمات، تداخل پورت و تمام مسیرهای مشترک را ببینید؛ سپس اعمال کنید. هر دو طرف بکاپ و تایمر بازگشت محلی دارند. ظرف ۹۰ ثانیه مسیر واقعی را بررسی و تأیید کنید؛ بدون تأیید، تنظیمات برمی‌گردد. توقف عمدی حفظ می‌شود.

۵. ابزارهای سرور: لاگ پوشیده، کانفیگ، مصرف منابع و بررسی شبکه. لاگ دقیق موقت خودکار محلی برمی‌گردد. عملیات گروهی هر سرویس را یک‌بار اجرا می‌کند. لغو مدیریت، فایل و سرویس را حفظ می‌کند.

۶. گواهی وارد یا صادر کنید. کلید خصوصی فقط به شنونده داده می‌شود؛ طرف مقابل گواهی اعتماد را می‌گیرد. تمدید و استقرار دو سیاست مستقل‌اند. شکست یک طرف، نتیجه و بازگشت قابل‌پیگیری دارد.

۷. بازیابی خودکار مخصوص سرویس مشخص است: آستانهٔ پیوسته، فاصله و سقف روزانه دارد و توقف عمدی را نقض نمی‌کند. هشدار را می‌توان دید یا موقتاً بی‌صدا کرد.

## معنی وضعیت‌ها
عامل متصل، پردازهٔ فعال، TCP موفق، TLS معتبر و پاسخ کاربردی پنج شاهد متفاوت‌اند. دادهٔ قدیمی یا قطع ارتباط سالم نمایش داده نمی‌شود. آمار ترافیک فقط رابط اندازه‌گیری‌شده را توصیف می‌کند؛ مصرف هر تونل یا صورتحساب کامل نیست. TCP سلامت VLESS را ثابت نمی‌کند.

نسخه یا تنظیم ناسازگار فقط‌خواندنی است و دلیل دارد. WSS در Backhaul 0.7.2 گواهی طرف مقابل را تأیید نمی‌کند؛ انتخاب آن پذیرش روشن می‌خواهد. بررسی TLS مستقل پنل رفتار موتور را عوض نمی‌کند. اتصال واقعی به ارائه‌دهندهٔ گواهی، DNS و تلگرام بدون حساب مالک آزمایش نشده است.

## نگهداری
مسیرهای پیش‌فرض: /opt/tunnelmanager، /etc/tunnelmanager و /var/lib/tunnelmanager. فقط HTTPS عمومی است. اسرار و عملیات پایدار در دیتابیس رمزگذاری می‌شوند؛ کلید اصلی بیرون دیتابیس است. عامل دستور محدود دارد؛ ترمینال وب و دستور دلخواه ندارد. SSH تغییر نمی‌کند.
```sh
sudo tunnelmanager status
sudo tunnelmanager doctor
sudo tunnelmanager backup --output /root/tunnelmanager.backup
```
